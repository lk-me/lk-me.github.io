linux下科学上网简单搭建

linux下利用shadowsock+kcptun+udp2raw的科学上网搭建。

本文适读人群

  1. 对 linux 服务有简单了解
  2. 对科学上网稳定性有强迫，在使用 shadowsocks+kcptun+udp2raw 会让科学上网非常稳定不容易掉包

本文能够知道什么

  1. linux 下成功使用 shadowsocks+kcptun+udp2raw 搭建科学上网
  2. 常见故障怎么定位（key 不一致、MTU 溢出、换网络后失效、TUN 冲突）

本文不知道什么

  1. 搭建工具原理

链路总览

先把数据流搞清楚，后面每一步都对得上号：

各环节端口对应关系：

环节 协议 端口
本机 SOCKS5 TCP 9872
sslocal → kcptun client TCP 30001
kcptun client → udp2raw client UDP 30001
udp2raw client → udp2raw server UDP 4096
udp2raw server → kcptun server TCP 8400
kcptun server → ssserver TCP 39201

30001 同时出现两次是正常的：kcptun 监听 TCP 30001 给 sslocal 连，udp2raw 监听 UDP 30001 给 kcptun 连，协议不同不冲突。

VPS 购买

  1. 我买的是 digitalocean 价格在 5 刀一个月偏贵，只要是国外服务器就行。

防火墙只要开一个口

  • 只需要放行 UDP 4096 入站，其它（22 除外）全部关掉。
  • 8400、39201 是纯本地回环，绑定 127.0.0.1 即可，不要对外暴露。

shadowsocks搭建

  1. 下载 shadowsocks 已发布的版本 https://github.com/shadowsocks/shadowsocks-rust/releases；
  2. 选 x86_64-unknown-linux-musl 那个包（静态链接，不依赖系统 glibc，扔到任何发行版都能跑）：
  1. 压缩包解压后我们要使用的有两个文件：ssserver（服务端）、sslocal（客户端）。

注意：新版 shadowsocks-rust 的配置文件字段改过（变成 servers / locals 数组），老版本用单个 JSON 对象的写法在新版会报错。下面统一改用命令行参数，跨版本最稳。

客户端配置

  1. 将 sslocal 拷贝至 /usr/local/bin/ 下
  1. 创建开机启动服务

参数含义：-b 本地 SOCKS5 监听地址；-s 上游地址，也就是 kcptun 客户端的 TCP 30001。

  1. 启动并设置开机启动

服务端配置

  1. 将 ssserver 拷贝至 /usr/local/bin/ 下
  1. 创建开机启动服务

**这里必须绑 127.0.0.1**。老版本照着抄 "server": "::" 会把 39201 暴露在公网，等于绕过 udp2raw + kcptun 直连 shadowsocks，既失去抗封锁效果又多一个被扫的入口。

  1. 启动并设置开机启动

kcptun搭建

  1. 下载 kcptun 已发布的版本 https://github.com/xtaci/kcptun/releases，选 linux-amd64 包（文件名形如 kcptun-linux-amd64-<日期>.tar.gz，日期随版本变，用最新的那个）：

国内访问 GitHub Releases 经常失败，可以从 SourceForge 镜像拿：https://sourceforge.net/projects/kcptun.mirror/files/，文件完全一样。

  1. 解压后要用两个文件：server_linux_amd64（服务端）、client_linux_amd64（客户端）。

客户端配置

  1. 将 client_linux_amd64 拷贝至 /usr/local/bin/ 下
  1. 创建开机启动服务

三个容易踩的点：

  • --mtu 1200 不能省。kcptun 默认 1350，加上 28 字节 IP/UDP 头就是 1378 字节，超过 udp2raw 单包上限 1375，日志会刷 huge packet,data len=1378 (>=1375)，表现为能连上但速度很怪。
  • --nocomp 必须和服务端 "nocomp": true 一致。
  • 老版本抄来的 PIDFile=/var/run/kcp-server.pid 是无效行——kcptun 不写 pid 文件，Type=simple 下写它只会让 systemd 打警告，删掉。
  1. 启动并设置开机启动

服务端配置

  1. 将 server_linux_amd64 拷贝至 /usr/local/bin/ 下
  1. 创建配置文件

mtu 两端必须一致，客户端 --mtu 1200 服务端就写 1200。
target 指向本机 ssserver 的 39201，listen 监听 8400，两个都在回环里，不要绑 0.0.0.0。

  1. 创建开机启动服务

ExecStart 里的文件名要和拷贝的文件名一致。官方包里的二进制叫 server_linux_amd64，不是 kcptun；两者不一致会直接 status=203/EXEC 起不来。

  1. 启动并设置开机启动

udp2raw搭建

  1. 下载 udp2raw 已发布的版本 https://github.com/wangyu-/udp2raw-tunnel/releases；
  2. 解压后使用对应架构的 udp2raw_amd64，udp2raw 服务端客户端是同一个文件。

客户端配置

  1. 将 udp2raw_amd64 拷贝至 /usr/local/bin/ 下
  1. 先看一个能跑但不够用的版本
  1. 实际推荐：加 --lower-level auto --source-ip --dev

udp2raw 的 faketcp 是自己在二层拼包发出去的。如果本机装了 Mihomo / Clash 之类会建 TUN 设备接管全局路由的软件，内核给它选的源地址会变成 TUN 的地址（比如 198.18.0.1），伪 TCP 的 SYN 会被对端直接 RST，日志永远是 client_tcp_handshake 反复重发 SYN。

需要显式告诉它走哪块网卡、用哪个源 IP：

--source-ip 必须填主路由表里的真实局域网 IP，不是 TUN 地址；--dev 是对应网卡。手工写死的问题是换个 WiFi 就失效，所以做成启动时自动探测的 wrapper：

  1. 开机启动服务
  1. 启动并设置开机启动

服务端配置

  1. 将 udp2raw_amd64 拷贝至 /usr/local/bin/ 下
  1. 创建开机启动服务

服务端 -a 会自动写 iptables 规则拦掉内核发的 RST，必须先装 iptables，否则启动直接失败：sh: 1: iptables: not found。
apt install iptables 即可。客户端不需要 -a（用 --lower-level 直达二层就没这个问题）。

  1. 启动并设置开机启动

密钥必须两侧一致

这是最容易出错的地方，三组独立的值、各自成对：

位置 客户端 服务端
shadowsocks 密码 sslocal -k ssserver -k
kcptun key / nocomp / mtu --key --nocomp --mtu "key" "nocomp" "mtu"
udp2raw key -k -k

任一处不一致的典型表现：**握手看起来成功，但一拿数据就 curl: (52) Empty reply from server**。

  1. 首先下载谷歌插件 SwitchyOmega
  2. auto switch 配置规则列表网址 https://raw.githubusercontent.com/gfwlist/gfwlist/master/gfwlist.txt
  3. proxy 配置代理协议 Socks5，代理服务器 127.0.0.1，代理端口为刚才 shadowsock 端口 9872

Chrome 新版本只支持 Manifest V3 扩展，SwitchyOmega 2 已从 Chrome 商店下架。Firefox 上仍可正常安装，Chrome 上可以换 SmartProxy 之类的替代品，或者直接用系统代理 / 终端方式。

终端配置科学上网

在 [ProxyList] 下增加（**协议名是 socks5，不是 sock4**）：

几个要点：

  • 段名是 [ProxyList]，不是 [Proxylist]（大小写敏感，写错整段不生效）。
  • 默认那行 socks4 127.0.0.1 9050 是给 tor 用的，删掉或注释，保留你自己的 socks5 127.0.0.1 9872。
  • 确认 proxy_dns 处于开启状态（新版默认就是开着的，行首没有 #），让域名也走代理解析，否则 DNS 泄漏且部分站点解析不到。
  • 用的时候：proxychains4 curl https://www.google.com。
  • 不想装 proxychains4 也可以单条命令指定：curl --socks5-hostname 127.0.0.1:9872 https://www.google.com。
